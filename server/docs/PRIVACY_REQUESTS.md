# 数据申请处理

用户可在「我的 → 隐私与安全」提交导出、删除案件数据、注销账户申请，查询最近 20 条记录及回复。
该入口是人工核验渠道，不会自动删除用户、OSS 文件或支付记录，不会自动退款。
重复提交同类型未结案申请返回原记录。用户只可读写自己的申请。

## 部署

按[部署指南](DEPLOYMENT.md)先在 staging 验收，再发布同一 SHA 的正式后端，最后构建并上传客户端。申请表由迁移 `0005_privacy_requests.sql` 创建；正常发布由迁移器应用所有待执行迁移，不单独重复执行此 SQL，不修改任何已应用文件。staging/production 均不得使用内存数据库。

## 运营处理

在阿里云服务器终端，先进入已发布的目标 release 的 `server/` 目录并加载对应环境配置，以具备所需读取权限的运维身份执行。当前配置文件权限及环境加载约定见部署指南；不能从其他目录依赖默认 `.env` 猜测目标。不要将环境文件或用户材料粘贴到聊天。

```bash
node dist/scripts/privacy-requests.js list
node dist/scripts/privacy-requests.js respond <申请编号> processing '已开始核验，请在本页关注回复。'
node dist/scripts/privacy-requests.js respond <申请编号> completed '经核验已完成对应处理，具体范围与保留原因如下……'
```

处理工具仅记录进度和回复，运营负责人应每日查看待办。只有实际完成数据交付、清除或注销后才可标记 completed。
回复可被申请人读取，不得包含其他用户资料、私钥或可公开访问敏感材料的地址。

1. 核验请求属于当前账户，明确涉及的案件、材料、导出范围和付费争议。不要通过产品反馈收集完整身份证或银行卡。
2. 导出：通过核验后的安全渠道交付账户、案件、材料、对话及报告资料；不要把公开 OSS 地址写入回复。
3. 删除：检查原始 OSS 文件、头像、结构化字段、对话、报告、缓存和备份；记录删除范围、时间及依法保留的内容和依据。
4. 注销：先处理未决支付及争议，并确认必要交易留存要求；清除或去标识化无需继续保存的账户和业务数据，验证既有会话不能再访问资料。
5. 对备份按实际备份轮换计划处理；恢复备份时重新应用已完成的删除请求，避免数据复活。不要将案件归档视为实际删除。
6. 记录真实处理结果及保留理由，然后更新状态。未核验或无法满足时用 rejected，并说明理由和后续联系渠道。

- 运营主体与联系邮箱已由负责人于 2026-10-19 确认，并写入 `miniprogram/src/content/privacy.ts`；发生变更时同步更新。
- 核实正式 AI 供应商、存储地域、数据留存与备份周期、第三方数据处理约定，补充到隐私说明。
- 配置微信后台的《用户隐私保护指引》，与客户端实际收集的信息一致；代码中的告知不替代平台配置。
- 确定数据申请的处理负责人及响应期限；未确定并落实前不得对外承诺“自动注销”或“立即删除”。
- 完成正式真机业务和受控支付验收；本地测试不代表真实支付或审核已通过。
