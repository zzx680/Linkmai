# 微信提审配置修复

> 历史记录：以下状态、测试结果和命令仅对应记录时的版本，不代表当前已部署、已验收或允许上线。旧部署、初始化和回退命令不要直接执行；当前操作统一见[部署指南](DEPLOYMENT.md)。


- 订单中心 path：`pages/payments/index`，不带参数、不重复。
- 此页面新增全部案件的全部状态订单记录、分页、订单号、金额、下单和支付时间及订单详情；归档案件不影响订单查询。无当前案件时仍能查看订单，未登录时在原页面登录。
- 新增 `GET /api/payment-orders?limit=20&offset=0`，最大每页 50 条。只按认证账户查询；返回展示必需字段，不返回预支付 ID、微信交易标识、幂等键等内部字段。列表读取不会创建订单或发起付款。
- 后端须先部署此接口，再上传含订单中心的新小程序；本地构建不会更新微信后台已有开发版。不存在该接口的旧后端会显示加载失败和重试入口，不伪装为空订单。
- 负责人本次确认正式环境使用 DeepSeek 官方 API。本地隐私政策已同步明确腾讯微信同声传译、阿里云 OSS/OCR 和 DeepSeek 的处理目的；平台补充文档见 `miniprogram/release/privacy-supplement.txt`。
- 微信后台隐私指引已完成预览，经负责人明确确认后勾选真实性承诺并点击提交协议；页面曾切换为只读指引。但刷新并从提审表重新打开后，页面回到初始选择，进入编辑器也未保留所填内容，因此不能认定平台已持久保存。未提交小程序代码审核。
- 无独立用户名密码，使用微信登录；不得为审核新增登录绕过或虚构测试凭据。

以上是修复说明，生产部署、平台保存和重新上传的实际结果须分别核验，不能以本地测试代替。
