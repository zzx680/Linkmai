## 支付验收与修复

负责人于本次会话确认已在真机完成「付款成功 → 权益解锁 → 报告可读」、取消支付和退款验收。本次审查采用这一人工验收结果，未再次发起真实扣款或退款；以下新修复通过自动化回归，部署后应复核对应流程。

- 金额和币种由服务端决定；新建及复用订单均返回原单金额。客户端拉起微信收银台前核对页面展示价格，缺失或不一致时刷新权益并停止付款。
- 同案件创建订单使用案件行锁，未决订单即使本地过期也须查单/关单确认。`USERPAYING`、创建结果未确认和关单竞态期间不创建替代订单；终态幂等键不能重新拉起旧单。
- 商户订单号使用密码学随机数；查单、支付回调验证订单、商户、AppID、用户关联、金额、币种和交易 ID。回调验签、时间窗口及解密测试通过，重复通知不会重复授予权益。
- 微信查单 `REFUND` 可能表示部分或处理中退款，不直接撤销权益。仅验签通过、原交易及金额一致、状态成功的单笔全额退款撤销该订单权益；旧退款回放不得撤销其他有效付款的权益。
- 部分退款保留权益；当前未实现多笔部分退款累计全额后自动撤权。运营如需关闭付费服务，应使用单笔全额退款流程，不能将部分退款组合视为已自动关闭。
- 未付费/已退款时当前案件接口不返回责任和赔偿结论，报告接口仍检查权益。报告生成期间若已完成退款，返回前再次核对权益，不交付付费内容。
- 退款后的首页入口改为付费记录；取消支付和待确认订单保留恢复路径，客户端回调成功不会直接视为已付费。

## 安全与隐私

- JWT 限定 HS256，并校验必需的用户身份字段；登录参数、幂等键和请求 ID 增加格式限制。
- 已认证接口按用户限流，登录按 IP 限流；限流表清理过期项并限制键数量。后端仅信任 loopback 代理。
- 对话、案件、材料、报告和订单保持用户/案件归属校验；对话更新事务化，材料变动后拒绝发布旧快照报告。
- 反馈和隐私申请校验参数、按用户隔离。运营主体和邮箱已按负责人确认写入隐私页，导出/删除/注销为人工核验申请，不宣称自动执行。
- 开发者工具启用域名/TLS 校验；H5 开发服务绑定本机；发布同步排除环境文件、支付私钥和本地工具配置。
- 当前仓库源码及待提交文件扫描未发现私钥块、典型云访问密钥或硬编码模型 token（模式扫描存在范围限制，不能证明所有秘密均不存在）。微信产物未发现旧网站 API、本机 API、测试 API 或 source map。
- 移除未使用的后端 `uuid`/类型包及前端 `ali-oss`，不删除历史源码或用户资料。
